Introduction

Read a business's services and availability, and create or cancel bookings on its behalf.

Base URL: http://demo.maw3idy.localhost:8000 
Every endpoint lives on the business's own subdomain, for example
`https://demo.maw3idy.app/api/v1/services`. The subdomain is what identifies the
business: there is no tenant id to pass, and a token issued by one business is not
accepted on another's subdomain.

Two kinds of endpoint:

- **Public reads** — the service catalogue and a service's availability. No token,
  throttled to 60 requests a minute per business and caller. This is what a booking
  widget needs.
- **Authenticated writes** — listing, creating and cancelling bookings. These need a
  token whose abilities cover the action.

All instants in requests and responses are UTC and carry an explicit offset
(`2026-10-05T07:00:00+00:00`). Each response also reports the business's timezone in
its `meta`, so you can render local times without guessing. Times you send may carry
any offset; they are converted on arrival.

<aside>Code examples for several languages are on the right (or in the content on mobile).</aside>

Authenticating requests

To authenticate requests, include an Authorization header with the value "Bearer {YOUR_AUTH_KEY}".

All authenticated endpoints are marked with a requires authentication badge in the documentation below.

Exchange a staff account's credentials for a token with POST /api/v1/tokens. A token belongs to one business: it only works on that business's own subdomain, and only for the abilities it was issued with.

Availability

When a service can be booked. Public, and throttled to 60 requests a minute.

Start times for a day

Returns the start times a customer could actually take: inside the staff's working hours, clear of existing bookings and their buffers, clear of time off, and in the future. Each slot lists the staff who could take it, so "anyone available" is one request, not one per person.

A slot can disappear between this call and a booking; creating a booking answers 409 in that case.

Example request:
curl --request GET \
    --get "http://demo.maw3idy.localhost:8000/api/v1/services/1/availability?date=2026-10-05&staff_id=1" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json"
const url = new URL(
    "http://demo.maw3idy.localhost:8000/api/v1/services/1/availability"
);

const params = {
    "date": "2026-10-05",
    "staff_id": "1",
};
Object.keys(params)
    .forEach(key => url.searchParams.append(key, params[key]));

const headers = {
    "Content-Type": "application/json",
    "Accept": "application/json",
};


fetch(url, {
    method: "GET",
    headers,
}).then(response => response.json());

Create a booking

requires authentication

Needs the bookings:write ability.

Omit staff_id to let the platform pick anyone who offers the service and is free. The slot is verified again under a lock before the booking is written, so two callers racing for the same time cannot both win: the loser gets 409.

The service's duration, buffer and price are copied onto the booking, so later changes to the service never rewrite an existing appointment.

Example request:
curl --request POST \
    "http://demo.maw3idy.localhost:8000/api/v1/bookings" \
    --header "Authorization: Bearer {YOUR_AUTH_KEY}" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"service_id\": 1,
    \"staff_id\": 1,
    \"starts_at\": \"2026-10-05T07:00:00+00:00\",
    \"customer_name\": \"Layla A.\",
    \"customer_phone\": \"+966501112222\",
    \"customer_email\": \"layla@example.com\"
}"

const url = new URL(
    "http://demo.maw3idy.localhost:8000/api/v1/bookings"
);

const headers = {
    "Authorization": "Bearer {YOUR_AUTH_KEY}",

Tokens

Getting and giving up API access.

Create a token

Send a staff account's email and password and receive a bearer token. Ask for abilities explicitly to be able to write; without them the token can only read.

Throttled to five attempts a minute per caller and per email address.

Example request:
curl --request POST \
    "http://demo.maw3idy.localhost:8000/api/v1/tokens" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"email\": \"owner@demo.test\",
    \"password\": \"password\",
    \"device_name\": \"Front desk iPad\",
    \"abilities\": [
        \"bookings:write\"
    ]
}"

const url = new URL(
    "http://demo.maw3idy.localhost:8000/api/v1/tokens"
);

const headers = {
    "Content-Type": "application/json",
    "Accept": "application/json",
};

let body = {
    "email": "owner@demo.test",
    "password": "password",
    "device_name": "Front desk iPad",
    "abilities": [
        "bookings:write"
    ]
};

fetch(url, {
    method: "POST",
    headers,
    body: JSON.stringify(body),
}).then(response => response.json());
